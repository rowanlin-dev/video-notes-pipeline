# 04 · 模型依赖与降级

> 管：视觉模型、文本模型、ASR、ffmpeg 之间怎么分工，缺谁时降级到哪一步。
> 什么时候读：换模型、加 API 端点、出现 429/超时/中文豆腐块/静默失败时。

---

## 1. 依赖分层

| 层 | 配置 | 用途 | 缺失时 |
|:--|:--|:--|:--|
| 视觉 | `VISION_API_KEY/BASE_URL/MODEL` | 帧打分、图内文字提取 | 跳过打分与提取，只能做脑图或纯文字笔记 |
| 文本 | `TEXT_API_KEY/BASE_URL/MODEL` | 分类、写正文 | 分类走启发式；正文需 `--emit-brief` 由宿主 Agent 写 |
| ASR | 本机 faster-whisper | 无官方字幕时转写 | 无字幕可写，需人工补字幕 |
| 渲染 | Edge/Chrome → weasyprint | PDF | Markdown 仍可用，PDF 跳过 |
| 媒体 | ffmpeg / PyAV | 抽帧、合流、转音频 | 流水线在第 1 步失败 |

**OpenAI SDK 是可选依赖**：`note_subject.py` 与 `md_note.py` 都必须在没有 `openai` 包时通过 `requests` 调 `/chat/completions`。

---

## 2. 降级矩阵

| 缺失 | 仍能做 | 降级策略 | 必须提示 |
|:--|:--|:--|:--|
| 无 `TEXT_API_KEY` | 分类、简报、Agent 写笔记 | 启发式分类 + `--emit-brief` | 日志说明“未配置文本模型” |
| 无 `openai` 包 | 全部文本能力 | 自动走 requests | 不提示（正常路径） |
| 无视觉 Key | 字幕笔记、脑图 | 跳过 Step 3/5 | 简报标注“无截图/无图内文字” |
| 视觉 429 | 部分帧 | 全局限流闸门 + 重试 5 次 | 失败帧数、可 `--from-step 3` 重跑 |
| 官方字幕缺失/串台 | 全部 | 自动 ASR | 日志标注 ASR 兜底 |
| 无 Chrome | Markdown | weasyprint + TTF 字体 | PDF 字体检查 |

---

## 3. 并发与限流

- 视觉请求默认 4 并发（`VISION_WORKERS`），免费档建议 2；
- 任一请求遇到 429/1113，其他线程在下一次请求前一起退避；
- **部分帧失败不判死**：成功帧照常落盘，下游只用成功帧；只有全部失败才非零退出；
- `--resume` 按文件名跳过，会把失败帧一起跳过；需要重打分时清空对应 JSON 后整目录重跑。

---

## 4. 错误提示约定

面向终端使用者（也是 Agent）：

- 每条失败必须包含：**哪一步、哪个文件、怎么恢复**；
- 不把上游原始报错直接抛成唯一信息（例如 `KeyError: 'data'` 无意义）；
- 静默降级只允许发生在“结果仍可用”的情况，且必须打印一行可检索的 `[warn]`；
- 不允许为了“跑通”而吞掉分类、提取、字幕缺失等影响质量的错误。

---

## 5. 成本边界

- 写正文的成本远低于视觉打分：20 分钟视频约 8k token；
- 缩略图/低分辨率不应影响打分，但会影响 OCR，需在简报中说明；
- 重跑优先 `--from-step`，避免重复下载与重复打分。

---

## 6. 条款来源

| 条款 | 来源 |
|:--|:--|
| openai 可选 | 历史上未装 SDK 时分类静默退化；同类问题也出现在 `md_note` 的 `call_llm` |
| 部分帧失败不中断 | 免费档 429 曾把整条流水线判死 |
| 降级必须可见 | 2026-11-19 对照实验：静默 general 让整轮实验的变量失真 |
