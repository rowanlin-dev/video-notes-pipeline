# 06 · 代码可读性与注释

> 管：Python 脚本怎么写才让人愿意读、敢于改。
> 什么时候读：新增脚本、重构阶段、PR 自查之前。

---

## 1. 这个项目需要什么样的“可读”

不是库，也不是大型服务，而是**一组按阶段运行的脚本 + 一份提示词**。因此：

- 读者通常是“三个月后的自己”或第一次提 PR 的贡献者；
- 一个函数的上下文往往跨 3–4 个文件（`run_pipeline` → 阶段脚本 → `md_note`）；
- 最贵的错误不是“命名不好看”，而是**改了这里不知道那里会崩**。

所以本项目的可读性优先级是：**边界清楚 > 报错可定位 > 命名准确 > 注释充分**。

---

## 2. 硬规则

1. **注释写 why，不写 what。** `# 取本分 P 时长，避免多 P 视频用整稿预算` 有价值；`# 设置 duration` 没有。
2. **禁止静默失败。** `except` 里要么恢复并打印 `[warn]`，要么重新抛出。允许“可选依赖缺失时降级”，但必须留一行可检索的日志。
3. **公开函数要有 docstring。** 至少说明：做什么、参数含义、返回什么、失败时怎样。内部小函数可以只写一句 why。
4. **新增脚本顶部必须有模块 docstring。** 写清：这个脚本属于哪个阶段、输入输出是什么、怎么单独运行。
5. **错误信息包含三件事：哪一步、哪个文件、怎么恢复。** 不要只抛 `KeyError: 'data'`。
6. **不提交注释掉的旧代码。** 用 git 记历史，不用注释存档。
7. **不在代码里硬编码 Key、Cookie、本机绝对路径。** 路径从 `ROOT`/参数推导。
8. **中文注释与中文错误提示是默认。** 标识符、API 名、日志关键词（如 `[warn]`、`[md]`）保持英文，方便检索。

---

## 3. 命名约定

| 对象 | 规则 | 反例 |
|:--|:--|:--|
| 阶段目录 | 固定三件套：`scene/`、`selected/`、`final/` | `frames2/` |
| 中间变量 | 体现来源：`sub_chars`、`evidence_chars` | `n1`、`tmp` |
| 布尔 | `has_*`、`is_*`、`*_enabled` | `flag` |
| 配置 | 与环境变量同名或可一一对应 | 自造缩写 |
| 兼容层 | 名字带 `compat` 或注释说明“仅为旧调用保留” | 悄悄改签名 |

---

## 4. 类型与结构

- **新增的公开函数建议标注类型**；不做全仓类型改造，也不引入 mypy 作为门槛。
- 一个函数只做一件事；超过约 80 行且出现两个明显阶段时，按阶段边界拆。
- 不为了“看起来整洁”把 20 行逻辑拆成 3 个文件；拆分判据见 `module-docs/README.md` §4。
- 数据在阶段之间只通过文件传递，不共享可变全局状态。

---

## 5. 日志与告警

- 统一前缀：`[pipeline]`、`[md]`、`[warn]`、`[scene]`、`[asr]`；
- `[warn]` 必须可 grep，且说明后果（“分类失败，使用启发式”“正文低于区间下限”）；
- 不允许 `except: pass`；不允许为了“跑通”吞掉影响质量的错误；
- 进度日志只打印阶段级事件，不逐帧刷屏。

---

## 6. 格式与依赖

- 不强制 `black`/`ruff`：本仓历史代码风格不统一，强行格式化会产生大量无意义 diff；
- 新增依赖先问“stdlib 能不能做”，其次看 `requirements.txt` 是否已有同类；
- 可选依赖（`openai`、PyAV、weasyprint）必须在 import 处降级，并在 `requirements.txt` 注释说明。

---

## 7. PR 自查清单

- [ ] 新增/修改的函数有 why 注释或 docstring；
- [ ] 所有 `except` 都有日志或重新抛出；
- [ ] 错误信息包含“哪一步、哪个文件、怎么恢复”；
- [ ] 没有硬编码路径、Key、Cookie；
- [ ] `python -m py_compile` 通过；
- [ ] 受影响的阶段能用 `--from-step N` 单独重跑；
- [ ] 改动涉及的文档已更新并标注 `[影响文档]`。

---

## 8. 条款来源

| 条款 | 来源 |
|:--|:--|
| 注释写 why | 本仓历史上“注释复述代码”多于解释原因 |
| 禁止静默失败 | 分类在缺 SDK 时静默返回 general，导致整轮实验变量失真 |
| 错误信息三件事 | 多次出现“只报 KeyError，不知道是哪个分 P 的哪个文件” |
| 不强制格式化 | 单人维护 + 脚本型仓库，格式 churn 的成本高于收益 |
