# 02 · 笔记篇幅预算

> 管：一篇笔记该写多长、怎么判断“压缩过头”或“在注水”。
> 什么时候读：改 `note_subject.py` 的预算逻辑、看到长度告警、准备调常数之前。

---

## 1. 第一性问题

字数是**结果**，不是任务。真实写作的顺序是：先按主题定大纲、按受众定讲法，字数自然落位。
所以系统只需要一个**区间**，用来判断两端异常：

- 低于下限：某些内容被压缩或遗漏；
- 高于上限：重复、复述口语、或注水。

字数**不应**由与内容无关的变量决定。时长、帧数、播放量、点赞数都不进入公式：
时长长不等于信息多（口播重复更多），帧数多只是采样密，不代表内容更丰富。

---

## 2. 现行公式（v1.6.3）

```
信息量 info = 字幕字符数 + 0.35 × 图中文字字符数
展开比 ratio = 1.4 / (1 + info / 12000)
受众系数 mult = 从业者 0.8 / 有常识的爱好者 1.0 / 零基础 1.35

下限 lo = clamp(info × ratio × 0.82 × mult, 800×mult, 45000)
上限 hi = clamp(info × ratio × 1.32 × mult, lo + 600×mult, 45000)
```

设计意图：

| 变量 | 为什么这样取 |
|:--|:--|
| 字幕字符数 | 最直接的内容量代理；口语重复会被展开比的收敛抵消 |
| 0.35 × 图中文字 | 纯演示/代码实录几乎没有口播，只看字幕会严重低估；但 OCR 只覆盖 8–12 帧，全量计入会虚高 |
| `1.4 / (1 + info/12000)` | 短素材展开 1.0–1.5 倍，长素材降到 0.1–0.2 倍；用常数 12000 控制拐点 |
| 0.82 / 1.32 | 区间带，约 ±25%；不是必须写满的任务 |
| 0.8 / 1.0 / 1.35 | 从业者可压缩，零基础要类比与铺垫 |
| 800 / 45000 | 极短素材仍有最低结构；超长内容防止无限膨胀 |

## 3. 场景推演（2026-11-19 实测口径）

| 场景 | 信息量 | 从业者 | 爱好者 | 零基础 |
|:--|--:|--:|--:|--:|
| 2 分钟极短口播 | 400 | 600–1,100 | 800–1,400 | 1,100–1,900 |
| 5 分钟短科普 | 1,340 | 1,100–1,800 | 1,400–2,200 | 1,900–3,000 |
| 6.7 分钟技术科普（本仓样例） | 3,916 | 2,700–4,400 | 3,400–5,500 | 4,600–7,400 |
| 10 分钟教程 | 5,280 | 3,400–5,400 | 4,200–6,800 | 5,700–9,100 |
| 20 分钟讲课 | 9,525 | 4,900–7,900 | 6,100–9,800 | 8,200–13,200 |
| 45 分钟课程 | 26,050 | 7,500–12,100 | 9,400–15,200 | 12,700–20,500 |
| 90 分钟长课 | 96,700 | 9,800–15,800 | 12,300–19,700 | 16,500–26,600 |
| 3 小时长课 | 181,050 | 10,300–16,600 | 12,900–20,800 | 17,400–28,100 |
| 静默代码演示 | 2,300 | 1,800–2,900 | 2,200–3,600 | 3,000–4,800 |
| 纯 PPT 讲座 | 16,050 | 6,300–10,200 | 7,900–12,700 | 10,600–17,100 |

判断标准：短素材比例高、长素材比例收敛、静默演示不再被低估；3 小时与 90 分钟的差距很小是**有意为之**——长课的口播与示例重复率更高，笔记不该线性膨胀。

---

## 4. 告警口径

`md_note.py` 在以下情况打印 `[warn]`：

- 正文低于下限：疑似输出能力不足或内容被压缩；
- 正文高于上限 × 1.15：疑似重复或注水。

⚠️ **口径不一致的已知问题**：代码里的长度检查统计“非空白字符（已剔除代码块）”，会把 URL、Markdown 标记、英文 API 名都算进去；而区间是基于中文字符量推的。两者只用于粗判，不应据此反复扩写。

---

## 5. 调参边界

允许调整：

- `12000`：拐点。素材普遍更短时调小，更长时调大；
- `0.82 / 1.32`：区间带宽。调宽只会让告警更少，不会让内容更好；
- `AUDIENCE_MULT`：只有新增受众层级时才改。

禁止：

- 为某个视频单独改常数；
- 把区间改成单一目标值；
- 重新引入时长/帧数/播放量作为输入。

## 6. 验证

- 改公式后先跑 `python scripts/note_subject.py` 的自测，再跑 §3 的推演表；
- 用同一视频 `--from-step 6` 重生成简报，确认三处一致：简报篇幅、`[md]` 日志、告警阈值；

## 7. 条款来源

| 条款 | 来源 |
|:--|:--|
| 字数由内容与受众决定 | 用户在 2026-11-19 明确指出：时长/帧数与内容无关，真实写作先定大纲再自然成篇 |
| 旧公式的两端失真 | 旧式 `600+35×时长+0.22×字幕+8×帧数` 对 6.7 分钟视频给出 29,358 字目标；更早的 0.025 系数又把 84 分钟课程压到 4–6k |
| 0.35 图中文字权重 | 推演“静默代码演示”时发现只看字幕会把 6,000 字图内信息算成 200 字 |
| 12,000 拐点 | 第一轮推演中 90 分钟长课上界达 3 万，正常笔记会误报，收敛后降至 2 万以内 |
