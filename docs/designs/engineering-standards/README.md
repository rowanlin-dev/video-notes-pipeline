> 管：这个项目里“永远要守的规矩”。
> 什么时候读：改流水线、调提示词、加参数、发版之前。

## 1. 为什么是 6 篇，不是母版的 12 篇

母版面向多端 Web 项目（前端/后端/联调/UI 文案/分支模型）。本项目是单体 Python 流水线，
以下几类条款不构成本项目的主要风险，已合并或外置：

| 母版篇目 | 本项目处理 |
|:--|:--|
| 01 文档体系与更新协议 | 保留，落在本目录 `README.md` + `docs/README.md` 的更新协议 |
| 02 迭代开工程序 | 保留，落在 `feature-designs/` 的三段式（需求 → 方案 → 实验） |
| 03 代码可读性与注释 | 保留为 `06-代码可读性与注释.md`；`CONTRIBUTING.md` 只留摘要与链接，避免两处漂移 |
| 04 模块拆分与解耦 | 合并进 `01-流水线契约与阶段边界.md`（按阶段边界拆，不按行数拆） |
| 05 接口契约与联调 | 本项目无 HTTP 服务，改写为 `api/README.md` 的 CLI/产物契约 |
| 06 验证与排错 | 保留，落在 `05-验证与回归.md` |
| 07 用户可见文案与错误提示 | 本项目的“用户”是终端使用者与 Agent，合并进 `04-模型依赖与降级.md` 的错误提示约定 |
| 08 分支与提交 | 外置到 `CONTRIBUTING.md` |
| 09 知识沉淀与回写 | 保留，作为本目录的维护规则（§3） |
| 10 文档归档与台账维护 | 合并进 `designs/README.md` §4 |
| 11 新对话交接 | 由 `docs/README.md` + `designs/README.md` 台账承担 |
| 12 AI 协作边界与人工拍板项 | 合并进 §3 的“必须人工拍板”清单 |

## 3. 知识回写与人工拍板

**新坑双写**：一条进根目录 `AGENTS.md`（自动注入层，只写结论），一条进本目录（现象、根因、正确做法）。

**必须人工拍板、AI 不得自行决定**：

- 更换默认 `TEXT_MODEL` / `VISION_MODEL`（影响成本与输出质量）；
- 放宽或收紧篇幅公式的常数（影响全部视频）；
- 修改产物格式（Markdown 结构、图号规则、时间戳格式）；
- 把任何真实素材（视频、字幕、截图）放进公开目录。

**旧结论作废时**：在原处写“已更正 + 新结论 + 日期”，不要只改新文档。
