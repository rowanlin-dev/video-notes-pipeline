# 迭代文档

> 管：每次“要动手改什么”的计划、方案与实验记录。
> 什么时候读：接手某个已完成迭代、或准备开新迭代时。

---

## 1. 命名

```
feature-designs/
└── YYYY-MM-DD-主题/
    ├── 01-需求与范围.md      要解决什么、不做什么、验收标准
    ├── 02-方案设计.md        备选方案、取舍、数据流、风险
    └── 03-对照实验.md        怎么验证、结果、局限、复现方式
```

主题用短横线连接的英文或中文短语，能一眼看出改的是哪一块。

---

## 2. 写法

- **01 只写“问题与目标”**：不写实现细节，不贴大段代码；
- **02 写“为什么这样选”**：至少列出一个被否决的备选与原因；
- **03 写“证据”**：指标、对照、失败样本、局限性；结论必须能追溯到数据。

计划与实际上线记录分开：上线后的变更进 `docs/changelogs/`，本目录不修改历史结论。
